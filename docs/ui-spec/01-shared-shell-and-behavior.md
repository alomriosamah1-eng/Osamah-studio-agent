# القشرة المشتركة وسلوك الواجهة

## نطاق الملف

يصف هذا الملف العناصر الموجودة حول الشاشات الأربع، وطريقة انتقال المستخدم بينها، وقواعد إظهار وإخفاء الأدوات السياقية. القشرة لا تنفذ وظيفة المجال بنفسها؛ هي تربط المستخدم بمكونات الشاشة الحالية وتعرض حالتها بأمان.

## المناطق الرئيسية

| المكوّن | الغرض | الظهور | المحتوى المسموح |
|---|---|---|---|
| هوية التطبيق | إظهار اسم Osamah Studio Agent وحالة التشغيل المحلية | دائم | الاسم، الإصدار، وصف local-first |
| تبويبات البيئات | انتقال مباشر بين البيئات الأربع | دائم على سطح المكتب | بيئة التطوير، Production Studio، Second Brain، مركز التحكم |
| Global Rail | تنقل مختصر بين البيئات | دائم على سطح المكتب، يتحول إلى شريط أفقي على العرض الصغير | أيقونة، اسم قصير، حالة التحديد |
| Project Sidebar | المشروع المفتوح وشجرة الملفات والمسارات السريعة | دائم في سياق المشروع | اسم المشروع، نوعه، شجرة bounded، روابط البيئات |
| Main Workspace | الشاشة النشطة الوحيدة | دائم | محتوى البيئة الحالية فقط |
| Inspector | مراقبة الحالة والموافقات والحوكمة | مخفي افتراضيًا | Human Gate، ملخص التشغيل، قائمة الموافقات، خريطة القدرات |
| Footer Status | الحالة المختصرة والفرع والذاكرة والملف التشغيلي | دائم | حالة محلية، اسم الشاشة، branch، memory mode، profile |
| إشعار الحالة | نتيجة إجراء أو خطأ أو عدم توفر | عند الحاجة | نص قصير، سبب، الإجراء الآمن التالي |

## الانتقال بين البيئات

توجد أربع قيم منطقية للشاشة النشطة: `development` و`studio` و`brain` و`settings`. عند اختيار قيمة، تُخفى كل الشاشات الأخرى، ويُعاد تمرير مساحة العمل إلى بدايتها، ويتغير عنوان النافذة وFooter وحالة Inspector. لا يفتح الانتقال أي مزود أو عامل أو اتصال شبكي.

| العملية | النتيجة المطلوبة |
|---|---|
| فتح بيئة التطوير | إظهار المحرر وتوجيه الوكيل وأدوات المشروع فقط |
| فتح Production Studio | إخفاء عناصر التطوير والمحاكي وإظهار أدوات الإنتاج فقط |
| فتح Second Brain | إخفاء أدوات الإنتاج والتطوير وإظهار الذاكرة فقط |
| فتح مركز التحكم | إخفاء أدوات العمل وإظهار الإدارة فقط |
| مغادرة بيئة التطوير | إغلاق المحاكي تلقائيًا |
| الضغط على Escape | إغلاق Inspector والمحاكي السياقيين |
| إعادة فتح الشاشة | العودة إلى بداية الشاشة دون الاحتفاظ بموضع تمرير شاشة أخرى |

## المحاكي وInspector

المحاكي جزء من بيئة التطوير وليس مكوّنًا عالميًا. يبدأ مخفيًا، ويظهر عند «فتح المحاكي» أو «تشغيل المعاينة»، ثم يتجاور مع المحرر على سطح المكتب. إخفاؤه لا يزيل حالة المشروع أو الملف المحدد. عند العرض المتوسط يتحول إلى عمود أسفل المحرر، ولا يسمح بفرض عرض جانبي يسبب تضييقًا غير عملي.

Inspector ليست عمودًا دائمًا. يبدأ التطبيق من دونها ومن دون عمود محجوز لها. يفتحها المستخدم من «المراقبة» أو «الموافقات»، وتحتوي على المعلومات التي يحتاجها لمراجعة الحالة أو Human Gate. لا تحتوي Inspector على محرر مستقل أو مسار تنفيذ منفصل.

## الشريط العلوي

| العنصر | الحقول أو الإجراءات |
|---|---|
| حالة التشغيل | محلي وآمن، مع مؤشر لون للحالة |
| فتح مشروع | استدعاء اختيار مجلد عبر المضيف، مع حالات الإلغاء والفشل |
| المراقبة | تبديل Inspector، مع `aria-expanded` |
| الموافقات | فتح Inspector على منطقة Human Gate وتحديث القائمة |
| اسم التطبيق | Osamah Studio Agent، ولا يستبدل باسم upstream |

## Project Sidebar

تحتوي القائمة الجانبية على بطاقة المشروع، شجرة الملفات، المسارات السريعة، ورسالة نطاق الأمان. شجرة الملفات تعرض metadata محدودة مثل الاسم، المسار النسبي، النوع، والامتداد. لا تعرض أسرارًا أو محتوى ملفات كاملًا في القائمة.

| حالة Sidebar | النص أو السلوك |
|---|---|
| لم يفتح مجلد | «جلسة جاهزة · لم يُفتح مجلد بعد» |
| انتظار الاختيار | «في انتظار اختيار مجلد» |
| إلغاء الاختيار | «تم إلغاء الاختيار» |
| فشل الاختيار | رسالة مختصرة مع بقاء التطبيق قابلًا للاستخدام |
| مشروع مفتوح | اسم الجذر، عدد الملفات أو metadata المتاحة |
| خطأ قراءة الشجرة | إبقاء آخر حالة سليمة وعدم إسقاط القشرة |

## Inspector ومراقبة الحوكمة

| القسم | المحتوى |
|---|---|
| رأس اللوحة | اسم Inspector، الشاشة الحالية، شارة local، زر إغلاق |
| Human Gate | عدد الموافقات، نطاق كل موافقة، نوعها، أزرار القرار المسموح |
| Runtime Summary | transport، fidelity، Fast Refresh، AI access |
| Safety Contract | ما سيقرأه النظام، وما قد يكتبه، وأين تذهب البيانات |
| Capability Map | مالك القدرة داخل Osamah، وحالتها: available أو deferred أو review-only |
| Timeline | أحداث مختصرة bounded دون أسرار أو محتوى خام |

الموافقة المحلية لا تعني تحققًا خارجيًا ولا تعني أن عملية حساسة أصبحت آمنة تلقائيًا. يجب أن تعرض الواجهة نطاق الموافقة ونتيجتها وسبب الرفض عند وجوده.

## قواعد الحقول

كل حقل يجب أن يملك اسمًا واضحًا، و`aria-label`، وقيمة ابتدائية آمنة، وحدًا أقصى مناسبًا، ورسالة عند القيمة غير الصالحة. محتوى المستخدم يعرض عبر عقد DOM آمنة ولا يحقن كـHTML. الحقول التي تتعلق بمسار أو أمر أو diff تستخدم اتجاه LTR، بينما الحقول العربية تستخدم RTL.

## حالات مشتركة

| الحالة | ما يظهر للمستخدم |
|---|---|
| loading | «جارٍ التحميل» مع تعطيل الإجراء المرتبط فقط |
| ready | البيانات والإجراءات المتاحة |
| empty | لا توجد بيانات مع شرح ما يمكن فعله لاحقًا |
| review_required | شارة مراجعة وسبب واضح وزر مراجعة إن كان متاحًا |
| unavailable | «غير متاح في هذا المضيف» دون زر تنفيذ مضلل |
| rejected | «رُفض الطلب» مع كود مختصر وسبب مفهوم |
| error | «تعذر إكمال الطلب» مع إبقاء البيانات السابقة إن كانت سليمة |

## اللغة والمظهر

القيمة الابتدائية للغة هي العربية واتجاه الصفحة RTL. يمكن اختيار English من مركز التحكم، مع بقاء identifiers والمسارات وأسماء العقود بالصيغة التقنية. يتغير المظهر من إعدادات التطبيق إلى داكن أو فاتح، ويغير حجم النص والكثافة وتقليل الحركة قيمًا عامة فقط. لا تؤدي هذه الإعدادات إلى فتح المحاكي أو Inspector.

## الوصول ولوحة المفاتيح

يجب أن تكون جميع الأفعال الأساسية قابلة للوصول عبر Tab وEnter وSpace. يوضح `focus-visible` موضع التركيز. التبويبات تستخدم `role="tablist"` و`role="tab"` عند الحاجة، وحالات التحميل والنتيجة تستخدم `aria-live="polite"`. زر Escape يغلق اللوحات السياقية دون تغيير البيانات. لا يستخدم التطبيق hover كوسيلة وحيدة لاكتشاف الإجراء.

## القيود غير القابلة للتجاوز

لا تعرض القشرة واجهة OpenCode أو Hermes أو DeepSeek، ولا تسمح بتعدد agent loops أو routers أو renderers لنفس القدرة. لا تحفظ الأسرار في localStorage أو DOM، ولا تحول رسالة المستخدم إلى أمر تنفيذي تلقائي. أي capability جديدة يجب أن تدخل عبر عقد Osamah typed IPC وبحارس صلاحيات مستقل.
