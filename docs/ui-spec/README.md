# ملفات وصف مكونات واجهات Osamah Studio Agent

هذه الحزمة تصف مكونات واجهات التطبيق وشاشاته وسلوكها وبياناتها وحالاتها وإجراءاتها. يمكن استخدام الملفات مباشرة كمرجع لتنفيذ الواجهة، من دون الاعتماد على واجهات المشاريع المفتوحة المصدر أو كشف تفاصيلها للمستخدم النهائي.

## ملفات الحزمة

| الملف | المحتوى |
|---|---|
| `01-shared-shell-and-behavior.md` | القشرة المشتركة، التنقل، الحالات العامة، لوحة المراقبة، قواعد الظهور، اللغة، الوصول، الرسائل، وسلوك سطح المكتب |
| `02-development-environment.md` | جميع مكونات بيئة التطوير: المشروع، الملفات، المحرر، توجيه الوكيل، المعاينة المدمجة، المهمة، الطرفية، Git، والموافقة |
| `03-production-studio.md` | جميع مكونات Production Studio: المصادر، الاستشهادات، الخطط، الأصول، الـBrief، الـArtifact، التقارير، والاستعداد للتصيير |
| `04-second-brain.md` | مكونات Second Brain: التقاط الذاكرة، البحث، المراجعة، المرشحون، والدمج |
| `05-control-center.md` | مركز التحكم: العامة، الحسابات، التخزين، الوكلاء، المزودون، التطوير الذاتي، الخصوصية، الأمان، الأداء، والتشخيص |
| `06-component-inventory.md` | سجل مختصر لكل مكوّن، معرفه، وظيفته، مدخلاته، أفعاله، وحالاته لاستخدامه كقائمة تحقق |
| `07-expanded-screen-catalog.md` | الشاشة الرئيسية، شريط الوكيل العام، مركز نشاط الوكلاء، المخرجات، الإدخالات، المحررات المتخصصة، ووحدات العمل والمعرفة الموسعة |

## تسلسل القراءة والتنفيذ

ابدأ بملف القشرة المشتركة لفهم العلاقة بين الشاشات وحالات الفتح والإغلاق. بعد ذلك اقرأ ملف بيئة التطوير لأنه يحتوي نقطة دخول توجيه الوكيل والمحاكي. ثم انتقل إلى Production Studio وSecond Brain، واختم بمركز التحكم والعناصر الإدارية. استخدم سجل المكونات في النهاية للتحقق من عدم سقوط أي عنصر.

## قواعد مشتركة ملزمة

> كل شاشة تطبيقية مستقلة، ولا تعرض شاشة أخرى داخلها. المحاكي ولوحة المراقبة أدوات سياقية لا تظهران إلا بطلب صريح. أي إجراء حساس يمر بالمراجعة البشرية ولا يتحول إلى تنفيذ ضمني.

| القاعدة | الوصف |
|---|---|
| اللغة الافتراضية | العربية، مع دعم الإنجليزية من إعدادات التطبيق |
| اتجاه النص | RTL للعربية، وLTR للكود والمسارات والطرفية وdiff |
| مصدر البيانات | عقود Osamah الداخلية فقط عبر طبقة IPC الموثقة |
| الأمان | لا أسرار في الواجهة، ولا عرض raw user files أو tokens |
| الوكلاء والمزودون | تعريفاتهم وحالاتهم تظهر عبر Osamah، ولا تظهر واجهات upstream |
| المحاكي | يظهر بجانب بيئة التطوير عند استخدامه فقط |
| الإعدادات | تظهر شاشة مستقلة عند استدعاء مركز التحكم فقط |
| العمليات الحساسة | review-first وHuman Gate وfail-closed |
| التخزين | محلي، مع بيان واضح إن كانت الحالة مؤقتة أو SQLite |
| حالات الفشل | رسالة مفهومة، دون محاولة تنفيذ بديل غير مصرح به |

## القاعدة الخاصة بالقدرات غير المنفذة

إذا لم توجد عملية تنفيذية في عقود التطبيق، يجب عرض العنصر كحالة `unavailable` أو `review-only` مع سبب صريح. لا يوضع زر يوحي بوجود تنفيذ فعلي، ولا تُستخدم أسماء مشاريع مفتوحة المصدر كأسماء شاشات أو routes.
