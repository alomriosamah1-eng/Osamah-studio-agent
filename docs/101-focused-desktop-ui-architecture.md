# معمارية واجهة سطح المكتب المركزة

## الغرض

تحدد هذه الوثيقة قواعد الواجهة الأمامية الموحدة لتطبيق **Osamah Studio Agent** بعد إعادة تنظيم التخطيط. الهدف هو منع التراكب والتعارض، إبقاء الشاشة الحالية مركزة، وإظهار الأدوات السياقية عند الحاجة فقط. الواجهة تخص Osamah وحده؛ أما OpenCode وHermes وأي مشروع upstream فتبقى خلف adapters أو workers ولا تظهر لها routes أو شاشات مستقلة للمستخدم.

## القاعدة الأساسية

> شاشة عمل واحدة نشطة في كل لحظة، ومحاكي أو Inspector يظهران فقط عبر استدعاء صريح. الانتقال إلى شاشة جديدة يخفي الشاشة السابقة وأي لوحة سياقية غير لازمة.

| المنطقة | السلوك الافتراضي | سلوك الاستدعاء |
|---|---|---|
| Global Rail | ثابت للتنقل بين البيئات | لا يفتح أدوات إضافية بذاته |
| Project Sidebar | ثابت في بيئة سطح المكتب لتحديد المشروع والملفات | يمكن تقليله لاحقًا إذا أضيفت حالة تركيز كاملة |
| Main Workspace | يعرض شاشة واحدة فقط من Home أو Development أو Production أو Brain أو Control Center | يتغير عبر `data-view` ويعاد تمريره إلى الأعلى |
| Home | الشاشة الأولى وبوابة اختيار البيئة | تخفي أدوات العمل الداخلية وتبقي شريط الوكيل العام فقط |
| Agent Instruction | شريط عام ثابت أسفل القشرة، ويمكن توسيعه عند الحاجة | ينتج معاينة محلية فقط ما لم يضاف عقد IPC صريح |
| Internal Section Navigation | يفصل نظرة عامة، المحرر، المراجعة، والسياسات داخل كل بيئة | يعرض مجموعة واحدة فقط في مساحة العمل |
| Embedded Simulator | مخفي عند البداية | يظهر بجانب المحرر عند «فتح المحاكي» أو «تشغيل المعاينة»، ويغلق مع Escape أو عند مغادرة Development |
| Inspector / Human Gate | مخفي ولا يحجز عمودًا فارغًا | يظهر عند «المراقبة» أو «الموافقات»، ويغلق بزر مستقل أو Escape |
| Control Center | شاشة مستقلة لا تظهر مع شاشة العمل | تستدعى من Global Rail أو تبويب مركز التحكم، وتعرض إدارة واحدة من التبويبات الإدارية في كل مرة |
| Status Footer | ثابت ويعرض الحالة المختصرة | يتغير باسم الشاشة النشطة وحالة النظام |

## تخطيط سطح المكتب

يستخدم `body-shell` اتجاهًا أفقيًا صريحًا (`direction: ltr`) لضمان ترتيب الأعمدة، بينما يضبط كل عمود داخلي اتجاهه إلى RTL. عند غياب Inspector يكون التخطيط: **Global Rail → Project Sidebar → Main Workspace**. عند استدعائها يضاف عمود Inspector فقط، ولا يُترك عمود فارغ عند إخفائها. أما المحاكي فهو جزء من Development Workspace وليس عمودًا عالميًا؛ وعند فتحه تتحول شبكة Development إلى محرر ومحاكي متجاورين، مع بقاء أدوات المهمة وTerminal وGit أسفلها ضمن الشاشة نفسها.

عند العرض المتوسط يتحول Development إلى عمود واحد ويُخفى Inspector. وعند العرض الصغير تتحول القشرة إلى ترتيب رأسي: الشريط العام، ثم Project Sidebar، ثم Main Workspace، مع تكديس محتوى المحاكي داخليًا. لا تعتمد الواجهة على overlay يغطي المحتوى الأساسي.

## شاشات المنتج

### بيئة التطوير الذكية

تبدأ الشاشة بمقدمة قصيرة وإجراءات واضحة، ثم مؤشرات الحالة ومحرر المشروع. لوحة **توجيه الوكيل** أصبحت شريطًا عامًا مشتركًا بين البيئات، مع بقاء المعاينة المحلية والإرسال للمراجعة فقط. المحاكي ليس جزءًا دائمًا من المشهد؛ يظهر فقط بعد طلب المستخدم. بقية الأدوات هي سياق متدرج: مراجعة المهمة، Terminal Policy للمعاينة فقط، وGit للقراءة فقط. لا يعرض أي زر تنفيذ غير موجود في عقود Osamah الحالية.

### Production Studio

تظهر شاشة الإنتاج مستقلة وتبدأ بمسار متسلسل من المصدر إلى artifact: Sources/Citations، Content Plan، Asset Catalog، Creative Brief، Artifact Review، Report Document، ثم Render Readiness. ويفتح تبويب **المحررات** محررًا واحدًا في كل مرة للمستندات أو العروض أو الصور أو الفيديو. كل لوحة توضّح إن كانت capability منفذة أو policy/review-only، ولا تظهر أدوات أو واجهات upstream.

### Second Brain

تظهر الذاكرة المحلية في شاشة مستقلة تبدأ بملخص اليوم، ثم توفر مساحات Today وWork وFinance وLearning وTasks وNotes & Knowledge، إضافة إلى التقاط الذاكرة والبحث lexical وقائمة المراجعة وMemory Consolidation. لا تعرض الشاشة embeddings أو vector search أو مشاركة تلقائية مع providers.

### Control Center

تظهر الإعدادات في شاشة مستقلة من Global Rail أو تبويب التحكم، وتشمل العامة، الحسابات الخارجية، التخزين، التطوير الذاتي، الوكلاء والمزودين، الخصوصية والأمان، الأداء والتشخيص، وحدود المحرر. لا تظهر إلا الإدارة المختارة داخل مساحة المحتوى. التوجيهات والاستراتيجيات والمخططات والمهارات تدخل كمرشحات `review_required` ولا تغير السياسة أو الصلاحيات تلقائيًا.

## لوحة توجيه الوكيل

| الحقل | الغرض | السياسة |
|---|---|---|
| التوجيه | النص الذي يحدده المستخدم للمهمة | مطلوب قبل إنشاء المعاينة |
| نوع المهمة | مراجعة وتحليل، خطة تنفيذ، شرح الكود، اقتراح diff | يحدد العرض فقط في الشريحة الحالية |
| النطاق | workspace أو نطاق أضيق | يظل نصًا محليًا ولا يفتح مسارًا تلقائيًا |
| الوكيل | الاختيار بين Auto · Osamah وCode workspace agent وKnowledge reviewer | تعريف واجهة محلي لا يفتح agent loop أو provider |
| القيود | حدود القراءة والكتابة والتنفيذ والموافقة | تُعرض للمراجعة وتبقى fail-closed |
| metadata | ربط معرفات وسياق محدود بالعمل الحالي | لا يرفع ملفات خامًا ولا ينفذ إرفاقًا تلقائيًا |
| سجل المهمة | فتح حالة النشاط والمراجعة في Inspector | لا ينشئ عملية نشطة ولا يغير Human Gate |
| معاينة التوجيه | تلخيص آمن للتوجيه المدخل | لا ترسل إلى agent أو provider ولا تنشئ تنفيذًا |

تستخدم المعاينة `textContent` وDOM APIs عند عرض النص المدخل، ولا تستخدم `innerHTML` للبيانات التي يكتبها المستخدم. الربط التنفيذي المستقبلي يجب أن يضاف عبر عقد typed IPC مستقل ومراجعة Human Gate، وليس عبر توسيع هذا الزر بصمت.

## حالات الشاشة

كل شاشة أو لوحة يجب أن تدعم الحالات التالية بصريًا، مع عدم الادعاء بقدرة غير متاحة:

| الحالة | التمثيل |
|---|---|
| loading | رسالة تحميل محدودة مع تعطيل الإجراء المرتبط |
| empty | شرح ما ينقص المستخدم لإظهار البيانات |
| ready | البيانات الحالية والأفعال المتاحة |
| review_required | إبراز أن المراجعة البشرية مطلوبة |
| error | سبب مختصر قابل للفهم مع بقاء الفشل مغلقًا |
| unavailable | توضيح أن المضيف أو العقدة غير متاحة دون محاولة بديلة غير مصرح بها |

## الوصول ولوحة المفاتيح

يجب أن تكون كل الإجراءات أزرارًا أو عناصر تحكم أصلية، مع `focus-visible` واضح، و`aria-label` للحقول والأجهزة، و`aria-live` للحالات التي تتغير. زر Escape يغلق Inspector والمحاكي السياقيين. عند إضافة command palette مستقبلًا يجب أن تستدعي نفس `activateView` ونفس دوال فتح اللوحات بدل إنشاء مسارات موازية.

## اللغات والمظهر

العربية هي اللغة الافتراضية مع `lang="ar"` و`dir="rtl"`. تبقى paths والكود وTerminal وdiff في LTR. إعدادات اللغة والمظهر وحجم النص والكثافة وتقليل الحركة موجودة في Control Center وتُطبّق عبر root data attributes وCSS variables. لا يجب أن يؤدي تغيير اللغة أو المظهر إلى إظهار شاشة سياقية كانت مغلقة.

## حدود التنفيذ الحالية

هذه الشريحة تنفذ Home، القشرة المركزة، الانتقال بين الشاشات، التنقل الداخلي لكل بيئة، الإظهار السياقي للمحاكي وInspector، شريط أوامر الوكيل العام، المحررات المتخصصة، وحدات Second Brain، وإدارات Control Center الإضافية، مع معاينة محلية فقط للتوجيه. لا تنفذ agent loop جديدًا، ولا ترسل توجيهًا إلى OpenCode أو Hermes أو DeepSeek، ولا تضيف renderer أو converter أو network capability. يبقى أي تنفيذ فعلي خلف العقود الحالية وHuman Gate.

## اختبارات الإغلاق

أغلقت هذه الشريحة باجتياز اختبار سطح الواجهة، فحص JavaScript وHTML، `pnpm check`، `pnpm desktop:smoke`، و`bash research/run-audit-gate.sh`، مع تسجيل فحوص بصرية للشاشات والتنقل الداخلي. كما يجب تسجيل فحص بصري لـDevelopment في حالته الافتراضية، وبعد فتح المحاكي، وبعد فتح Inspector، ثم فحص Production Studio وSecond Brain وControl Center بعد الانتقال إليها.
