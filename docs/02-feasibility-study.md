## الفرص الأقوى

أقوى فرصة هي توحيد **سياق المشروع والملفات والذاكرة والمهارات والمزوّدات** في تطبيق واحد، لأن المستخدم لا يحتاج إلى نقل المعرفة يدويًا بين IDE وNotion وأدوات الإنتاج. فرصة ثانية هي بناء provider routing محلي أولًا؛ OmniRoute يثبت أن registry والـ fallback والـ cost-aware dispatch سطح معماري واقعي [1]. فرصة ثالثة هي الاستفادة من المهارات القابلة للتثبيت والـ plugin seams بدل بناء كل تكامل داخل النواة، كما يظهر في Hermes وDeepSeek Harness [2] [3].

## أصعب المشكلات

أصعب مشكلة ليست إنشاء chat، بل ضبط **الأفعال عالية الأثر**: تشغيل أمر، تعديل ملفات، إرسال بيانات، نشر commit، أو استدعاء MCP. المشكلة الثانية هي context engineering عند المستندات الكبيرة والمهام المتعددة؛ الحل هو سجل أحداث قابل لإعادة التشغيل، ضغط سياق، واسترجاع انتقائي. المشكلة الثالثة هي الصوت العربي عالي الجودة، خصوصًا اللهجات؛ وجود مشاريع عربية لا يضمن جودة إنتاجية أو حقوق توزيع. المشكلة الرابعة هي عدم تعريف OpenTo.

## الاختناقات المعمارية

الاختناق الأول هو تشغيل runtime Python وNode وRust داخل تطبيق سطح مكتب واحد. يجب اختيار process boundary مع بروتوكول JSON-RPC/HTTP محلي، بدل محاولة ربط كل شيء داخل نفس العملية. الاختناق الثاني هو قاعدة بيانات متعددة الاستخدامات؛ SQLite ممتاز كبداية، لكن embeddings ضخمة وفهرسة ملفات كثيرة قد تحتاج LanceDB أو Qdrant محليًا كخدمة اختيارية. الاختناق الثالث هو تراكم الاعتماديات الأصلية مثل `node-pty` و`better-sqlite3` وPlaywright؛ يجب أن يكون CI متعدد الأنظمة وأن توجد مسارات degraded mode.

## التكاليف الخفية

تشمل التكاليف الخفية وقت اختبار Windows وmacOS، توقيع الحزم، تحديث Electron/Chromium، تنزيل النماذج، صيانة أوزان الصوت، تشغيل browser automation، بناء الفهارس، وتدقيق SBOM. كما أن provider المجاني قد يملك حدود حصة أو شروطًا تغير القرار الاقتصادي. لذلك لا يسجل النظام كلمة «مجاني» كحقيقة ثابتة؛ يسجل `cost_policy`, `quota`, `license`, و`last_verified_at` لكل provider.

## افتراضات غير واقعية يجب تحديها

افتراض «70 وكيلًا متزامنًا» يجب استبداله بـ **70 تعريفًا قابلًا للتثبيت مع concurrency limit**. افتراض «إنتاج غير محدود» يجب استبداله بقيود حجم ووقت وذاكرة مع queue. افتراض «دعم كل الأنظمة والنسخ» يجب أن يتحول إلى Windows 11 وLinux حديث كـ Tier 1، وmacOS كـ Tier 2 بعد توفر signing/CI. افتراض «صوت بشري يمني جاهز» يبقى research item لا acceptance criterion.

## قرار الجدوى

القرار هو **GO مشروط** لـ Discovery وMVP، و**NO-GO** لبناء النسخة الشاملة الآن. بوابة الانتقال إلى V1 هي: نجاح benchmark لخمس مهام، تحقق أمني من tool approval، تشغيل offline، استرجاع ذاكرة دقيق، وتوثيق OpenTo رسمي.
