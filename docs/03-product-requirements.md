# متطلبات المنتج

## الرؤية وقيمة المستخدم

يحتاج المستخدم إلى بيئة واحدة يفهم فيها الوكيل المشروع والملفات والمهام والملاحظات، ثم ينفذ الأعمال القابلة للتفويض مع إبقاء القرار البشري حاضرًا في الأفعال الحساسة. القيمة الأساسية هي تقليل تبديل الأدوات، لا زيادة عدد النماذج أو الوكلاء.

## البيئات الثلاث

| البيئة | النتيجة الأساسية | ما تشاركه |
|---|---|---|
| Intelligent Software Development Environment | تغيير برمجي قابل للمراجعة مع Git diff واختبارات | workspace، agents، skills، providers، memory |
| Production Studio | مستند أو عرض أو ملف وسائط مع مصدر ونسخة وإخراج | projects، artifacts، citations، rendering jobs |
| Second Brain | معرفة قابلة للبحث مرتبطة بمهام ومشاريع ومصادر | notes، documents، embeddings، permissions، activity |

## الجهات الفاعلة

الجهة الأساسية هي **مالك مساحة العمل**. توجد جهة ثانوية هي **الوكيل** الذي يعمل وفق policy ولا يملك صلاحيات تلقائية. وهناك **المزوّد** الذي يقدم نموذجًا أو خدمة، و**خادم MCP** الذي يقدم أدوات خارجية، و**المشرف** في التثبيت الجماعي، و**المهندس/الوكيل اللاحق** الذي يقرأ handoff والقرارات. لا يُفترض وجود multi-user في MVP، لكن تصمم هويات البيانات بحيث لا تمنع الإضافة لاحقًا.

## حدود النظام

يدخل إلى النظام طلب المستخدم، الملفات المحلية، Git repository، بيانات provider، ومصادر البحث المسموح بها. يخرج منه رد محادثة، خطة، diff، artifact، citation set، log، وقرار موافقة. تقع خارج الحدود في MVP خدمات الدفع، الحسابات السحابية الخاصة، OpenTo غير الموثق، والتوزيع التلقائي على الإنترنت.

## قصص المستخدم

| المعرّف | القصة | معيار النجاح |
|---|---|---|
| US-001 | بصفتي مستخدمًا، أريد فتح مشروع محلي ورؤية حالته كي أبدأ من سياق صحيح | تظهر الملفات وGit status وpolicy خلال 3 ثوانٍ بعد فتح مشروع مفهرس |
| US-002 | أريد طلب خطة قبل تعديل الملفات كي أراجع الأثر | يعرض النظام خطوات وملفات متأثرة ومخاطر قبل التنفيذ |
| US-003 | أريد اعتماد أمر terminal حساس صراحة | لا ينفذ الأمر المصنف عالي الخطورة دون approval event |
| US-004 | أريد تبديل المزوّد دون تغيير الميزة | يختار provider registry مزوّدًا آخر مع حفظ سبب الاختيار |
| US-005 | أريد تحويل بحث إلى تقرير | يحفظ المصادر والاقتباسات ويولد Markdown قابلًا للتصدير |
| US-006 | أريد العثور على ملاحظة قديمة بالعربية والإنجليزية | يعيد البحث النصي والسمعي النتائج مع project scope |
| US-007 | أريد تشغيل جلسة دون اتصال | يعمل المشروع والملفات والذاكرة المحلية مع رسالة واضحة عن الميزات المعطلة |
| US-008 | أريد أن أوقف الأتمتة أو أستعيد حالة سابقة | توجد pause/cancel وcheckpoint وrollback موثق |

## معايير المنتج

المنتج الجيد لا يساوي «أكبر عدد ميزات». يكون جيدًا عندما يكون مفهومًا، سريع الاستجابة، قابلًا للتراجع، صريحًا بشأن مصدره، ويمنع الوكيل من تجاوز الحدود. كل ميزة جديدة يجب أن توضح: ما البيانات التي تقرؤها، ما الأفعال التي تنفذها، ما صلاحيتها، وكيف يراجع المستخدم أثرها.
